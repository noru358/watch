# 🖥️📱 플랫폼·입력

← [1 기준](README.md)

**담당 코드:** `src/core/InputManager.ts`, 키 배치 `src/data/input.data.ts`

## ✅ 결정
- **PC와 모바일을 같이 간다(사용자 2026-11-19).** 같은 코드(Phaser + TypeScript)를 PC는 Electron, 모바일은 Capacitor로 감싼다. 게임성은 그대로이고, 모바일 때문에 바뀌는 것은 입력과 화면 읽기뿐이다. 포장(스토어 빌드)은 여전히 스팀이 먼저다.
- **화면은 가로 고정.** 세로로 들면 "가로로 돌려 주세요"가 뜬다.
- 시점: 비스듬한 탑다운 픽셀아트, 한 화면 ≈ 광장 하나.
- 한 판 길이는 미정(10~15분 vs 5분 안팎, [기획 방향](direction.md)). 모바일을 생각하면 짧은 쪽이 유리하고, 의뢰 목표마다 길이를 다르게 하는 안이 있다([의뢰 목표](../2-night/objectives.md) "목표 달성 시 귀환").

## 터치 조작 (✅ 2026-11-19 지어짐)
**담당 코드:** `src/ui/touch/TouchControls.ts`(화면 위 스틱·버튼), 배치는 `input.data.ts`의 `TOUCH`.
- 첫 터치(또는 터치 기기)에서 켜진다. 데스크톱 브라우저에는 안 보인다.
- 왼쪽 절반 어디든 엄지를 대면 그 자리에 스틱이 생긴다(떠 있는 스틱). 밤에는 아날로그 방향, 사무소와 메뉴에서는 W/A/S/D로도 읽힌다.
- 오른쪽 버튼은 키를 그대로 누른다: 밤 = 베기(J)·돌진(Space)·발도(K)·기술(L)·일시정지(Esc), 밤 메뉴(일시정지·카드·공중전화) = 선택(J) + 스틱 좌우, 사무소 = E. 그래서 화면들은 터치와 키보드를 구분하지 않는다(ARCHITECTURE 규칙 4).
- 조준: 손가락이 하나뿐이라 두 번째 스틱이 없다. 움직이는 중에도 4.5칸 안의 가장 가까운 괴이를 본다(`FEEL.touchAimRange`), 없으면 스틱 방향.
- 밤 HUD의 기술 칸 줄은 터치일 때 화면 아래 가운데로 옮겨 버튼에 가리지 않게 한다(발도 받아치기 신호가 거기 뜬다).
- 낮 창(의뢰판·장부 등)과 대화창은 손가락으로 직접 누른다. 창 오른쪽 위 "닫기"도 누르면 닫힌다.

## 모바일에서 아직 안 되는 것
- **낮 창 글자가 폰에서 너무 작다.** 844×390 폰에서 1280×720 무대를 0.54배로 줄이므로 작은 글자(11px)는 6px 남짓이 된다. 낮 UI를 인쇄물 한 벌로 다시 짤 때(로드맵 4) 폰에서 읽히는 최소 글자 크기를 같이 정한다.
- 카드 선택·공중전화는 스틱 좌우 + 선택 버튼으로만 고른다(카드를 직접 누르기는 아직 없음).
- 버튼이 쿨다운·받아치기 신호를 직접 보여 주지 않는다(신호는 가운데로 옮긴 HUD 칸에 있음).
- 실제 폰에서 손으로 해 본 적 없음. 헤드리스 크롬의 폰 크기(844×390, 터치)로 이동·베기·일시정지만 확인했다.

## 모바일을 위해 지금부터 지킬 것
| 항목 | 규칙 |
|------|------|
| 전투 버튼 | **4개 이하** — 지금: 베기 J · 돌진 Space · 발도 K · 액티브 기술 L (+ 이동, PC는 마우스 조준). 모바일은 가상 스틱 + 버튼 넷, 조준 보정 |
| 화면 비율 | PC 16:9 / 폰 19.5:9 → 중요한 UI는 가운데 **안전 구역**에만 |
| 입력 | InputManager에 `touch` 입력(가상 스틱, 탭 이동) 자리 마련. 키보드·패드·터치 모두 같은 "행동"(이동/공격/회피…)으로 번역 |
| UI 표시 | 같은 기능을 PC는 단축키 글자, 모바일은 큰 아이콘으로 |

## 🤔 남은 것
- 모바일 스토어 빌드(Capacitor 포장, 가로 고정 설정)는 스팀 포장과 같은 때. 지금은 브라우저에서 폰으로 확인한다.

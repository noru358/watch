# 🧭 기획 방향 — 무엇이 정해졌고 무엇이 열려 있나

← [1 기준](README.md) · 마지막 정리 2026-10-26. 새 결정이 나면 이 문서부터 고친다. 결정마다 자세한 내용은 링크한 모듈 문서 하나에만 있고, 여기는 한 줄 요약이다. 할 일 순서는 [로드맵](../roadmap.md).

## 이 게임은 (한 줄)
낮엔 중소기업 직장인, 밤엔 부업으로 을지로 옥탑방 퇴마 사무소장인 귀차니스트 해결사가 의뢰를 받아 밤에 괴이를 베고, 동료를 모으고, 월세를 막으며 사무소를 키우는 게임. 하데스형 탑다운 액션 로그라이트에 가벼운 사무소 경영과 캐릭터 수집을 얹는다.

## ✅ 확정 (바뀔 수는 있지만 지금은 이걸 기준으로 만든다)
- 세계·톤: 서울 생활감 + 시티팝, 은혼식 만담, 공포는 양념 → [세계관·톤](world.md)
- 주인공: 투잡 귀차니스트 소장, 신문지 사인검, 월세 압박 → [주인공](../2-night/protagonist.md)
- 밤 전투: 코어키퍼식 실시간 탑다운, 모든 공격은 바닥 예고, 발도(받아치기·일섬), 3타 콤보 → [전투](../2-night/combat.md)
- 큰 고리: 의뢰 → 출동 → 정산 → 사무소 → 다음 의뢰. 밤 1판 = 하루, 7일마다 월세.
- 사무소는 걸어다니는 실내 허브, 상시 메뉴 줄 없음 → [허브](../4-day/hub.md)
- 낮 고리(2026-10-26 "그렇게 만들어줘"): 시간의 탐험대식 의뢰판(메인 스토리 / 일반 의뢰 = 목표 6종 중 하나 + 현장 변형), 을지로 작전 지도의 동네 오염과 확산, 같은 동네 의뢰 묶기 → [의뢰판·작전 지도](../4-day/contracts-map-ops.md)
- 층 구조: 시작에서 가장 먼 방이 출구, 계단은 그 층의 목표를 끝내야 열림(섬멸·수색 구조 구현, 나머지는 [의뢰 목표](../2-night/objectives.md)) → [이야기 의뢰·층](../2-night/contract.md)
- 의뢰 종류 다양화(2026-10-26 ㅇㅋ): 턴제 의뢰를 그대로 옮기지 않고 실시간 구조로 바꾼다(호위·도주를 숫자가 아니라 층 구조로). 주목표를 끝내면 그 자리에서 귀환을 고를 수 있다 → [의뢰 목표](../2-night/objectives.md)
- 돈 쓸 곳(2026-10-26 ㅇㅋ): 돈으로 소장 단련 + 무기 손질 + 사무소 시설, 트라우마에 효과와 회복 → [성장·시설·트라우마](../3-growth/progression.md)
- 화면(2026-10-26 선택): 의뢰판 A, 밤 HUD C + A의 체력·진심 + 층수, 대화창은 이야기 A·잡담 B. 의뢰판엔 글 대신 지표 넷(목표·난이도·길이·보수) → [화면·UI](ui.md)
- 그림: 사용자는 도트를 찍지 않고 판정만 한다. 프레임은 마스터 한 장을 고쳐서. 그래픽 손질은 지금 수준으로 두고 나중에 → [그림 작업 절차](../5-business/art-pipeline.md)
- 숨은 규칙(공식·숫자 위치)은 [규칙 장부](../../rules/README.md)에 모듈별로 둔다(사용자: "그래야 수정하지")
- 1인 개발 범위 관리: 게이트마다 재미부터 확인하고 넓힌다 → [로드맵](../roadmap.md)

## 🤔 열려 있음 (사용자 생각 + 정할 때 볼 점)
**타이틀 화면** — A(옥상 야경, 세로 메뉴)와 B(네온 간판) 둘 다 좋다고 해서 합친 안을 만들었다. 사용자 확인 대기 → [화면·UI](ui.md).

**주인공 외형** — [주인공](../2-night/protagonist.md)의 2026-10-25 사양은 "중단발 레이어드, 성별 미정"인데, 게임에 들어간 그림(Gemini 1차 시트 → 마스터)은 가슴께까지 오는 긴 머리라 여성으로 읽힌다. 그림을 사양에 맞춰 다시 뽑을지, 사양을 지금 그림에 맞출지 정해야 한다. 정해질 때까지 그림 작업은 지금 마스터 기준.

**큰 이야기와 엔딩** — 사용자와 같이 고민한다. 틀 후보와 지금 있는 조각은 [이야기](story.md).

**첫 출정과 구미호** — 사용자: 첫 출정은 튜토리얼처럼 "센 괴이 하나 퇴치"로 할까 고민 중. 구미호를 동료로 데려가는 건 미정. 결정 전까지 지금 이야기 의뢰(「불 꺼지는 동네」, 보스 구미호)를 그대로 쓴다.

**영입 방식과 인간 동료** — 사용자: 에피소드 영입은 이야기를 살리기 좋고, 확률 영입은 과금(소녀전선 캐릭터 카드, 등급, 옵션)에 좋다. 아직 모르겠다 → [영입](../3-growth/recruit.md). 인간 퇴마사 동료를 둘지도 미정(1인 사무소 느낌과 부딪힘).

**분대 작전(파견)의 무게** — 설계안은 [의뢰판·작전 지도](../4-day/contracts-map-ops.md) "분대 작전". 첫 동료가 정해져야 만든다. 사용자 처음 생각: 소녀전선 군수작전처럼 "보내 두면 자원을 캐 오는" 정도, 크게 바뀔 수 있음. 정할 때 볼 점: 동료를 밤에 데려갈지 작전에 보낼지의 배분 고민이 생기면 낮이 대기실에서 벗어난다. 자동 수입은 밤 플레이 수입을 넘지 않는다(ARCHITECTURE §4).

**한 판 길이** — 10~15분 vs 5분 안팎. 잘하는 봇 기준 이야기 의뢰 약 2~4분, 사람 측정 필요. 의뢰 목표마다 끝나는 층을 다르게 해서 길이를 의뢰로 고르게 하는 안이 있다.

**그 밖** — 한 판 강화 카드를 계속 둘지(판 안 = 카드, 판 밖 = 동료·사무소로 나누는 안), 고양이 역할, 대여 시장·무기 B의 필요성.

## 참고로 받은 제안 (다른 AI, 2026-10-26, 채택 여부 미정)
분대 자동 작전을 핵심 축으로 삼되 직접 출동과 서로 돕게(주인공의 단서가 작전을 돕고, 작전 정보가 탐색·보스전을 돕기), 을지로 작전 노드 5~8개, 액션 맵의 작은 단서 줍기, 영입 = 에피소드, 이야기 4막과 은혼식 운용(일상 의뢰는 그 자체로 재미있게). 그쪽은 실시간 전투·발도·투잡 설정·게이트 구조를 모르는 상태였고, 한 판 강화 카드가 빠져 있으며 "서울에 종속시키지 않는다"는 점이 지금 기준과 부딪힌다. 노드 지도와 이야기 틀은 이미 받아들였다([의뢰판·작전 지도](../4-day/contracts-map-ops.md), [이야기](story.md)).

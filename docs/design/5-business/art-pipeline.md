# 🛠️ 그림 작업 절차 (1인 + AI 도트 파이프라인) — 2026-10-26

← [아트 모듈](art.md) · 그림체·크기 결정은 art.md가 기준이고, 이 문서는 "누가 어떤 도구로 어떤 순서로 만드나"만 다룬다. Gemini에 넣는 문장은 [그림 프롬프트 모음](art-prompts.md).

## 원칙
지금까지 막힌 지점은 셋이었다. 그림마다 비율·굵기·색이 따로 논다. 프레임을 장마다 새로 그리게 하니 픽셀이 30% 넘게 달라져 번쩍인다(그래서 코드로 머리를 고정하는 `stableHead`가 생김). 한두 픽셀 손질을 할 사람이 없다. 외부 사례의 결론도 같다: 범용 이미지 AI는 "도트처럼 보이는 그림"만 주므로 후처리가 필수이고, 애니메이션이 가장 약하며, 판단은 게임 화면에서 한다.

그래서:
- 프레임은 새로 생성하지 않고 **마스터 한 장을 고쳐서** 만든다(머리 픽셀이 처음부터 같아 번쩍임이 없다).
- 기준(팔레트·키·굵기)은 사람 눈이 아니라 **도구가 검사**한다.
- **사용자는 도트를 찍지 않는다(2026-10-26 결정).** 판정만 한다.

## 역할
| 누가 | 하는 일 |
|------|--------|
| 사용자 | 게임 화면 비교 이미지를 보고 OK / 다시. Gemini·PixelLab 웹에서 생성 버튼 누르기(AI가 직접 못 부르는 동안) |
| Gemini | 새 캐릭터·귀신의 첫 디자인, 대화창 초상화 |
| PixelLab | 마스터에서 동작 프레임(뼈대 애니메이션, 영역만 다시 그리는 inpaint), 4·8방향, 타일셋. 무료 40회로 시험 → 채택하면 MCP로 붙여 AI가 직접 호출 |
| AI(Claude) | 정리 스크립트, 팔레트 강제, 한두 픽셀 손질(외곽선 색·눈·잡티·발 높이), 마스터 레이어 나누기, 다리만 바꾼 걷기 같은 기계적 수정, 비교 이미지 생성, 게임에 연결. 주인공을 처음부터 그리지는 않는다(7차까지 해 보고 폐기한 이력) |
| 에디터 LibreSprite(무료) | 결과를 확대해 보는 용도. 필수 아님 |
| 외주(선택지) | 주인공·스팀 대표 이미지를 나중에 도트 작가에게 다듬게 하는 안. 에셋 팩은 그림체가 안 맞아 배경·소품에만 고려 |

## 종류별 길
- 주인공·동료(오래 보임): Gemini로 디자인 → 서 있기 한 장을 마스터로 확정 → 동작 프레임은 마스터에서(PixelLab 또는 AI 스크립트). Gemini 동작 시트는 자세 참고용.
- 귀신·보스: 그림 1~3장 + 움직임은 코드(둥둥·일렁임·번쩍임).
- 타일·소품·간판: artlab 글자 격자(AI, 견본 통과 이력 있음) 또는 PixelLab 타일셋.
- 대화창 초상화: 64~96px. Gemini → 정리 → 감정 3~4개는 입·눈썹만 바꿈(AI 스크립트).
- 이펙트·분위기: 코드.

## 마스터 한 장 (주인공)
새로 뽑지 않는다. 게임에 들어간 `v3:0`(빈손 서 있기, 눈 손질 적용)을 32×36 캔버스에 발 맞춰 옮긴 것이 `assets/master/director-master.png`(확대본 `@8x`), 그 26색이 `assets/palette/master.gpl`(32색까지 6칸 여유)이다.

남은 손질(AI가 스크립트로, 결과는 비교 이미지로 확인):
1. 외곽선에 섞인 보라 계열(`#22011e`, `#40043a`)은 분홍 배경 제거의 흔적이다. 바깥 외곽선을 `#0a0308` 하나로 통일한 판과 그대로 둔 판을 게임 화면에서 비교해 고른다.
2. 머리(머리카락 포함) / 몸통 / 앞팔 / 뒷팔 / 앞다리 / 뒷다리로 나눈 부품 PNG를 만든다. 가려진 몸통 픽셀은 이웃 색으로 채운다.
3. 동작 프레임은 머리·몸통을 고정하고 팔·다리 부품만 옮기거나(걷기) PixelLab inpaint로 팔 영역만 다시 그린다(콤보·발도).

필요한 프레임(오른쪽만, 왼쪽은 반전): 서 있기 1(숨쉬기는 코드로 몸 전체 1px), 걷기 4, 3타 콤보 각 타격 1 + 회수 1(6), 발도 자세 1·베기 1(납도는 자세 재사용), 돌진 1, 피격 1, 쓰러짐 1, 위쪽 공격 뒷모습 1. 약 16장. 나중에 뒷모습 걷기 2.

얼굴·비율이 마음에 안 들어 마스터를 다시 뽑을 때의 프롬프트는 [그림 프롬프트 모음](art-prompts.md) "주인공".

## 한 장이 게임에 들어가기까지
1. **생성**(사용자 또는 AI): Gemini는 새 대화에 1차 시트와 게임 스크린샷을 파일로 첨부, 공통 규칙 → 그림 하나당 메시지 하나, 3~4번 뽑아 실루엣·비율이 제일 나은 것 하나. PixelLab은 마스터를 올리고 바꿀 영역만 칠한다. 원본은 `assets/source/<도구>/<대상>-v<번호>.png`, 안 쓰는 건 `-rejected`.
2. **정리**(AI): `python3 tools/spritekit/clean_sheet.py 원본 결과폴더` → 격자 복원, 배경 제거, 덩어리 자르기, 팔레트 맞추기, 확대 미리보기. 키나 굵기가 틀리면 손대지 말고 다시 뽑는다.
3. **손질**(AI): 위 "남은 손질" 같은 기계적 수정을 스크립트로. 한 번만 도는 표시 파일(`face_edit.done` 방식)을 남긴다.
4. **판정**(사용자): 새 그림을 주인공 옆 실제 바닥·조명 위에 붙인 비교 이미지로 본다. 분홍 배경에서 판단하지 않는다. 볼 것: 키·굵기가 맞나, 보라 조명 아래서 읽히나, 바닥에 묻히지 않나, 움직일 때 번쩍이지 않나.
5. **연결·기록**(AI): `src/data/sprites.data.ts` 또는 해당 `draw/` 파일 → `npm run check` → 커밋. `assets/README.md`에 어떤 도구로 만들었는지 한 줄. 스팀은 2026년 1월부터 게임 안에 실제로 들어간 AI 생성물을 신고하게 하므로 이 기록이 신고 근거다.

## 아직 없는 도구 (AI가 만들 것)
고정 팔레트 강제(지금은 시트마다 24색), 키·굵기·팔레트 밖 색 검사, 게임 화면 비교 이미지 자동 생성, 마스터 부품 나누기.

## 첫 시험 과제
주인공 걷기를 두 방법으로 만들어 게임 화면에서 비교: PixelLab(사용자가 웹에서 마스터 올리고 걷기) / AI 부품 스크립트(다리만 바꿈). 이긴 방법을 주인공·동료 프레임의 기본 길로 정한다.

## 참고: 소울나이트식 분석 검토 (사용자 자료)
대부분 맞고 우리 방식과 같다: 무기는 몸과 따로 그려 조준 방향으로 회전, 2방향 + 좌우 반전, 돌진·피격은 그림 1장 + 코드 연출, 타격감은 이펙트에 투자, 피격 1장·공격 2~3장. 고칠 점: 공격은 "준비 → 타격 → 후딜"이 아니라 누르는 순간 맞으므로 타격 자세가 먼저(준비 동작은 발도에만 0.12초). 서 있기 바운스는 그림 교체가 아니라 코드 1px. "접촉-내림-통과-밀침" 걷기는 옆모습 기준이라 2등신 탑뷰는 4장 + 머리 고정이 핵심. "상·하체 분리"는 본문 근거가 없어 소울나이트의 사실로 쓰지 않고 우리 제안(부품 나누기)으로 쓴다. 칼자국은 코드 잔상(이미 있음).

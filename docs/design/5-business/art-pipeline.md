# 🛠️ 그림 작업 절차 (1인 + AI 도트 파이프라인) — 🤔 제안 (2026-10-26)

← [아트 모듈](art.md) · 그림체·크기 결정은 art.md가 기준이고, 이 문서는 "실제로 무엇을 깔고 어떤 순서로 손을 대나"만 다룬다.

## 왜 이렇게 바꾸나
지금까지 막힌 지점은 세 개였다. 그림마다 비율·굵기·색이 따로 논다(지하철 망령 첫 시도 8등신, 귀신 견본은 주인공보다 픽셀이 두 배 굵음). 프레임을 장마다 새로 그리게 하니 픽셀이 30% 넘게 달라져 번쩍인다(그래서 코드로 머리를 고정하는 `stableHead`가 생김). 한두 픽셀 손질을 스크립트(`face_edit.py`)로 하고 있다.

1인 개발자들의 공통 결론도 같다. 범용 이미지 모델은 "도트처럼 보이는 그림"을 줄 뿐이라 격자·팔레트·외곽선 후처리가 필수이고, 애니메이션이 가장 약하다. 오래 보이는 캐릭터일수록 사람 손이 가야 하고, 대량 소품·변종에서 AI 효율이 가장 좋다. 판단은 게임 화면에서 한다.

그래서 원칙을 셋으로 바꾼다.
- 프레임은 새로 생성하지 않고 **마스터 한 장을 고쳐서** 만든다(머리 픽셀이 처음부터 같으니 번쩍임이 없다).
- 기준(팔레트·키·굵기)은 사람 눈이 아니라 **도구가 검사**한다. 누가 그렸든 같은 문을 통과해야 들어온다.
- 한두 픽셀 손질은 **에디터에서 사람이** 한다.

## 0단계 — 기준 고정 (한 번, AI 담당)
- 프로젝트 고정 팔레트 `assets/palette/master.gpl`(32색 안팎): 주인공 1차 시트 24색 + 귀신·조명용 몇 색. 모든 정리 결과를 이 팔레트로 강제한다(지금은 시트마다 24색).
- 숫자 기준: 칸 24px, 주인공 약 34px 높이, 외곽선 1px `#0e0a10` 계열, 한 그림 안 픽셀 굵기 1.
- 검사 스크립트: 키·픽셀 굵기·팔레트 밖 색·외곽선 끊김을 재서 통과/불통과를 찍는다.
- 게임 화면 비교 이미지: 새 그림을 주인공 옆 실제 바닥·조명 위에 1.75배로 붙여 PNG로 뽑는다.

## 1단계 — 설치 (맥, 사람 담당, 한 번)
에디터는 하나만 고른다. 표준은 Aseprite(유료 약 $20, 일회성, aseprite.org 또는 스팀). 무료로 가려면 Pixelorama(무료·오픈소스, PixelLab 기능 통합) 또는 LibreSprite. PixelLab 확장을 쓰려면 Aseprite 1.3 이상이 필요하다.

AI 도구:
- 제미나이: 지금처럼 웹에서. 디자인(새 캐릭터·귀신의 첫 모습) 담당.
- PixelLab: 계정만 만들면 무료 40회. 마스터를 고치는 inpaint(영역만 다시 그리기), 뼈대 애니메이션, 4·8방향 돌리기, 타일셋. 써 보고 채택하면 월 $12부터, 그때 Claude Code에 MCP로 붙여 AI가 직접 부를 수 있다.

정리 도구 의존성(이미 쓰던 것):
```
pip3 install numpy pillow
```

## 2단계 — 무엇을 어떤 길로 만드나
- 주인공·동료(오래 보임): 디자인은 제미나이 → 서 있기 한 장을 **마스터**로 확정 → 동작 프레임은 마스터를 복사해 팔·다리·머리카락만 바꾼다(PixelLab inpaint 또는 에디터 손작업). 제미나이 동작 시트는 "자세 참고 그림"으로만 쓴다.
- 귀신·보스: 그림 1~3장 + 움직임은 코드(둥둥·일렁임·번쩍임). 제미나이나 PixelLab 한 장 → 팔레트 강제.
- 타일·소품·간판: artlab 글자 격자(Claude가 그림, 견본 통과 이력 있음) 또는 PixelLab 타일셋. 수량이 많아지면 후자.
- 대화창 초상화(이야기 장치용, 새로 필요): 64~96px 큰 그림. 제미나이 → 정리 → 감정 3~4개는 입·눈썹만 바꾼 손작업.
- 이펙트·분위기: 코드(지금처럼).

## 3단계 — 생성 (사람 담당, 제미나이 기준)
1. 새 대화를 연다. 주인공 1차 시트(`assets/source/gemini/director-sheet-v1.png`)와 최신 게임 스크린샷을 **파일로** 첨부한다.
2. [Gate 1 그림 명세](gemini-asset-specs.md)의 공통 규칙을 붙여 넣는다(배경 #FF00FF, 8배 확대, 2등신, 같은 픽셀 굵기).
3. 그림 하나당 메시지 하나. 같은 요청으로 3~4번 뽑아 제일 나은 것 하나만 고른다(고르는 기준은 실루엣과 비율, 디테일은 나중에 고침).
4. 원본을 `assets/source/gemini/<대상>-v<번호>.png`로 저장. 안 쓰는 건 `-rejected`를 붙여 남긴다.

PixelLab로 프레임을 만들 때: 마스터 PNG를 올리고, 바꿀 영역(팔·칼 쥔 손 등)만 마스크로 칠한 뒤 inpaint로 "arm raised behind head" 같은 자세 설명을 넣는다. 머리·몸통은 칠하지 않는다.

## 4단계 — 자동 정리 (AI 담당)
```
python3 tools/spritekit/clean_sheet.py assets/source/gemini/<파일>.png assets/sprites/<이름>
```
격자 되돌리기 → 배경 제거 → 덩어리 자르기 → **고정 팔레트로 강제**(0단계 뒤) → 검사 리포트 → 확대 미리보기(`contact.png`). 검사에서 굵기·키가 틀리면 손질 전에 다시 뽑는다(손으로 고칠 수준이 아님).

## 5단계 — 손질 (사람 담당, 에디터)
1. 정리된 `frame_XX.png`를 연다. 색 모드를 Indexed로 바꾸고 `master.gpl`을 불러온다(팔레트 밖 색을 못 찍게).
2. 고치는 순서: 외곽선 끊김·잡티 → 눈·입(1~2px) → 손 위치 → 실루엣.
3. 애니메이션은 마스터 프레임을 복제해 만든다. Onion skin(앞뒤 프레임 반투명 겹쳐 보기)을 켜고, 발이 땅에 닿는 줄(아래에서 2px)과 몸통 중심이 프레임마다 같은지 본다. 루프는 마지막→첫 프레임 이음새를 따로 확인.
4. 작업 파일(`.aseprite`)은 `assets/source/aseprite/`에, 내보낸 PNG는 `assets/sprites/<이름>/`에 둔다.

## 6단계 — 게임 화면 판정 (AI가 뽑고 사람이 본다)
비교 이미지를 보고 판단한다. 분홍 배경이나 확대 미리보기에서 판단하지 않는다. 볼 것: 주인공과 키·굵기가 맞나, 보라 조명 아래서 읽히나, 바닥에 묻히지 않나, 움직일 때 번쩍이지 않나.

## 7단계 — 연결·기록 (AI 담당)
`src/data/sprites.data.ts` 또는 해당 `draw/` 파일에 연결 → `npm run check` → 커밋. `assets/README.md` 목록에 어떤 도구로 만들었는지 한 줄 남긴다. 스팀은 2026년 1월부터 게임 안에 실제로 들어가 플레이어가 보는 AI 생성물을 신고하게 하므로, 이 기록이 상점 신고 문구의 근거가 된다.

## 마스터 한 장 (2026-10-26)

**무엇을 마스터로 쓰나.** 새로 뽑지 않는다. 디자인 기준은 이미 1차 시트이고, 게임에 들어간 실물은 `v3:0`(빈손 서 있기, 눈 손질 적용)이다. 이것을 32×36 캔버스에 발을 맞춰 옮긴 것이 `assets/master/director-master.png`(확대본 `@8x`), 그 26색이 `assets/palette/master.gpl`이다(32색까지 6칸 여유). 얼굴·비율이 마음에 안 들 때만 아래 프롬프트로 다시 뽑는다.

**에디터에서 마스터 완성하기 (사람, 한 번, 30분 안팎):**
1. `director-master.png`를 열고 Indexed + `master.gpl`.
2. 외곽선 정리: 테두리에 섞인 보라색 계열(`#22011e`, `#40043a`)은 분홍 배경 제거의 흔적이다. 바깥 외곽선은 `#0a0308` 하나로 통일할지 그대로 둘지 여기서 정한다(게임 화면에서 비교).
3. **레이어를 나눈다**: 머리(머리카락 포함) / 몸통(자켓·터틀넥·사원증) / 앞팔 / 뒷팔 / 앞다리 / 뒷다리. 팔·다리에 가려 있던 몸통 픽셀은 채워 그린다(팔을 움직이면 드러나므로). 칼 쥐는 손은 앞팔 끝의 1~2px 점이고, 칼은 그리지 않는다.
4. `assets/source/aseprite/director-master.aseprite`로 저장.

**동작 프레임 만들기:** 머리·몸통 레이어를 잠그고 팔·다리 레이어만 옮기거나 그 부분만 다시 그린다. 그러면 머리 픽셀이 모든 프레임에서 같아서 코드의 `stableHead` 땜빵이 필요 없어진다. PixelLab inpaint를 쓸 때도 팔·다리 영역만 칠한다.

**필요한 프레임 (지금 결정 기준, 오른쪽만 그리고 왼쪽은 반전):** 서 있기 1(숨쉬기는 그림을 바꾸지 않고 코드로 몸 전체를 1px 오르내림), 걷기 4, 3타 콤보 각 타격 1 + 회수 1(6장), 발도 자세 1·베기 1(납도는 자세 재사용), 돌진 1(잔상은 코드), 피격 1(흰 번쩍임은 코드), 쓰러짐 1, 위쪽 공격 뒷모습 1. 약 16장. 나중에 뒷모습 걷기 2.

**다시 뽑아야 할 때의 제미나이 프롬프트** (1차 시트와 게임 스크린샷 첨부, 공통 규칙 먼저):
```
Use the attached sheet as the master design. Draw ONE frame only: the character standing still, right-facing 3/4 view, empty hands, arms relaxed at the sides so the torso is fully visible, legs slightly apart with both feet flat on the same row. Art size 32x36, feet on the 3rd row from the bottom. Same face, hair, outfit, colours, outline and 2-head proportions as the sheet. Eyes calm and a little open (blue iris 2 px tall). No weapon, no effects.
```
팔을 몸에서 살짝 떼고 다리를 벌리게 하는 이유: 레이어를 나눌 때 가려진 부분이 적어야 한다.

## 소울나이트식 분석 검토 (사용자 자료, 2026-10-26)
대부분 맞고 우리 방식과 같다: 무기는 몸과 따로 그려 조준 방향으로 회전, 2방향 + 좌우 반전, 돌진·피격은 그림 1장 + 코드 연출(잔상·흰 번쩍임·찌그러뜨리기), 타격감은 몸 관절보다 칼자국·이펙트에 투자, 피격 1장·공격 2~3장.

우리에 맞게 고칠 점:
- **공격 순서.** 자료는 "준비 → 타격 → 후딜"인데, 우리는 버튼을 누르는 순간 맞는다(반응성 결정). 준비 자세를 앞에 넣으면 입력이 늦게 느껴진다. 그래서 타격 자세가 먼저, 회수가 나중이다(이미 결정). 준비 자세는 발도에만 0.12초 둔다(의도된 긴장).
- **서 있기 2~4장 바운스.** AI 프레임은 장마다 다시 그려져 바꿔 끼우면 번쩍인다. 마스터를 손으로 만들면 그림을 바꾸지 말고 코드로 1px 오르내리면 된다.
- **걷기 "접촉-내림-통과-밀침".** 옆모습 기준 설명이다. 2등신 3/4 탑뷰는 다리가 짧아 4장이면 충분하고, 핵심은 머리가 흔들리지 않는 것이다.
- **"상·하체 분리".** 첫 줄에 적혀 있지만 본문에 근거가 없다. 소울나이트에서 확인한 사실로 쓰지 말고, 우리 쪽 제안(마스터를 머리·몸통·팔·다리 레이어로 나누기)으로 쓴다.
- **칼자국 이펙트 3프레임.** 우리는 그림이 아니라 코드로 그리는 초승달 잔상을 쓴다(이미 들어감).

## 첫 시험 과제
주인공 3타 콤보 프레임(명세 0-B)을 세 방법으로 만들어 비교한다: 제미나이 4차 시트 / PixelLab inpaint(마스터 = `v3:0`) / 에디터 손작업. 판정 기준은 게임 화면에서 번쩍임이 없고 칼질이 읽히는가. 이긴 방법을 주인공·동료 프레임의 기본 길로 정한다.

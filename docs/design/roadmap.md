# 🗺️ 게이트 로드맵 — 지금 할 일과 점검

← [기획 모듈 지도](README.md) · 마지막 정리 2026-10-29. 게이트의 정의와 장기 구조는 이 문서(아래), 무엇이 확정이고 열려 있는지는 [기획 방향](1-foundation/direction.md). 이 문서는 "지금 무엇이 남았고, 어떤 순서로, 그게 정말 그 게이트 일인가"만 다룬다. 게이트를 끝내거나 순서가 바뀔 때마다 고친다.

원칙: 게이트는 **재미 질문** 하나에 답하는 단위이고, 그 질문에 필요 없는 일은 그 게이트의 일이 아니다. 그래서 그림·소리 마무리는 게이트에서 떼어 내 옆에서 계속 도는 **아트·사운드 트랙**으로 둔다.

## Gate 1 — 밤 전투 (기능 완성, 사용자 판정 대기)
**재미 질문:** 사무소장 혼자 신문지 사인검으로 한 밤을 깨는 게 손맛 있고 또 하고 싶은가?
**통과 기준(제안):** 사용자가 서너 판을 해 보고 "베기·발도·돌진이 손에 붙고, 예고를 읽어 받아치는 게 재밌다"고 말할 것. 지금 숫자는 전부 봇으로 맞춘 것.
**남은 일:** 사용자 플레이 → 손맛 숫자 재조정, 한 판 길이 측정 → 목표 길이 결정.

## Gate 2 — 사무소와 성장 (진행 중)
**재미 질문:** 밤이 끝나고 사무소로 돌아오면 "다음 밤도 가고 싶다"는 이유(돈 압박, 키우는 재미, 다음 의뢰 고르기)가 생기는가?
**통과 기준(제안):** 게임 안 일주일(월세 한 번)을 돌았을 때 의뢰 고르기·돈 쓰기·트라우마가 다음 밤의 선택을 실제로 바꿀 것.

**들어간 것:** 걸어다니는 사무소, 날짜·월세·빚, 의뢰판(메인 스토리 + 일반 의뢰 목표 7종 + 현장 변형 + 합동 출동 + 긴급), 작전 지도(오염·넘침·사건 파일), 메인 스토리 장(0장 → 1장 → 2장), 평판 등급, 트레이닝·기술·장신구·시설·보급품·트라우마, 아침 보고, 화면 개편, 저장. 자세한 순서는 [작업 기록](../history.md), 지금 할 일은 `HANDOFF.md`.

**남은 것:** 사용자 플레이와 숫자 조정, 글꼴 셋·톤 3을 화면 전체에, 진정제 아이템, 무기 손질, 남은 목표(행렬 호위 → 회수 → 도전장), 3장과 두 번째 지역([지역](4-day/regions.md)).

**사용자 결정이 먼저인 것(2-B 동료):** 영입 방식, 첫 동료, 큰 이야기 → [기획 방향](1-foundation/direction.md). 결정되면: 동행 슬롯 1 + 호출 스킬(버튼 넷 중 하나와 자리 나눔) + 동료 카드 3장 → 분대 작전 최소판.

**MVP 성공 기준(제안):** ① 직접 출동 한 판이 손맛만으로 또 하고 싶다(Gate 1). ② 낮에 "어느 의뢰를 받을지, 무엇을 키울지" 고민이 실제로 생긴다(Gate 2). ③ 의뢰 하나의 이야기를 끝까지 보고 싶다(Gate 2).

## Gate 3 — 서울 지도와 2군 파견 (아직)
**재미 질문:** 구역을 하나씩 정화해 나가는 큰 그림과, 쉬는 대원을 보내 두는 소소한 수입이 "내 사무소가 커진다"는 느낌을 주는가?
**할 일:** 서울 지도(을지로 지도를 구역 단위로 넓힘), 구역 2~3개(구역당 타일셋 1 + 괴이·보스·이야기 의뢰), 경리를 통한 파견(상한, `(시작, 끝, 상태)` 순수 함수 — 규칙 7), 꾸미기, 동료 슬롯 2개와 시너지 카드([동료와 강화 카드](3-growth/party.md)). 일반 귀신 확률 영입은 동료가 여럿 필요해지는 이 게이트에서 의미가 커진다. 파견 수입 상한은 테스트로 고정.

## Gate 4 — 대여 시장 (아직)
NPC 사무소와의 대여(오프라인으로 완결) → Supabase, 서버가 능력치 재계산·수수료 정산(규칙 7). **점검:** 대여가 왜 재밌는지(빌려 오면 무엇이 좋고, 빌려주면 무엇을 잃나)가 아직 기획에 없다. Gate 3 끝날 때 기획부터.

## Gate 5 — 스팀 출시 (아직)
Electron 포장, Steamworks(업적, 클라우드 저장), 영어 번역 손질. **빠진 것:** 키 바꾸기·화면 설정, 게임패드, 업적 목록, 상점 페이지 자료(캡처·트레일러), 성능 점검. Gate 3 무렵부터 목록 관리.

## 아트·사운드 트랙 (게이트와 병행, 통과 조건 아님)
사용자 결정(2026-10-26): 그래픽은 지금 수준으로 두고 나중에. 절차는 [그림 작업 절차](5-business/art-pipeline.md). 순서: 도구(고정 팔레트 강제·검사·게임 화면 비교 이미지·마스터 부품) → 주인공 걷기 시험(PixelLab vs AI 부품 스크립트) → 주인공 콤보·뒷모습 → 지하철 망령·칼·테마별 타일·소품 → 구미호 패턴 자세 → 사무소·경리·고양이·대화 초상화 → 한글 간판 → 효과음·배경음(소리 기획 문서도 이때). 주인공 외형 문제(사양 vs 지금 그림)는 [기획 방향](1-foundation/direction.md).

## 아직 없는 모듈
유물·아이템(Gate 3, 새 `items` 모듈), 소리(효과음은 임시 합성음, 배경음 없음 — 트랙), 키 바꾸기·게임패드·업적(Gate 5), 튜토리얼·첫 밤 안내, 동료·영입·파견(2-B).

## 장기 구조 메모 (2026-10-29 ARCHITECTURE.md에서 옮김 — 사용자 "장기적인 건 로드맵으로")
- 큰 고리: 낮(사무소 경영, 2군 자동 파견은 정화된 동네에만·상한 있음, 트라우마 회복, 대여 시장, 지도에서 오늘 밤 고르기) ↔ 밤(직접 조작하는 출동). 주 수입은 밤 플레이에서 나오고, 낮 자동 수입이 직접 플레이를 넘으면 안 된다.
- 대여 시장(Gate 4)과 서버: 퇴마사 능력치는 늘 순수 함수 `computeExorcistStats`로 계산하고 최종값을 저장하지 않는다 — 나중에 서버가 같은 함수로 다시 계산하고 수수료를 정산하기 위해서. 2군 파견·대여 수수료는 백엔드가 생기면 서버 시간 기준, 그때까지는 `(시작, 끝, 상태)`의 순수 함수로 둔다. NPC 사무소부터(오프라인), 그다음 Supabase. 인기도 수수료 감쇠는 퇴마사가 아니라 사무소 계정 단위.
- 출시(Gate 5): Electron + steamworks.js(업적, 클라우드 저장), 영어 현지화 점검. 모바일은 스팀 출시 뒤(터치는 입력 관리자 안의 입력원 하나로 추가).
- 범위 밖(따로 말하기 전까지): 모바일 빌드, 대여 경제와 묶인 실제 결제, 실시간 멀티플레이.

**담당 코드:** `src/data/lobby.data.ts`, `src/scenes/hub/`, `src/ui/features/`

## 1. 목표: "덕지덕지 금지"

참고한 게임 로비들의 문제점:
- 재화가 5~6개씩 상단에 줄줄이 → 뭐가 중요한지 모름
- 이벤트 배너, 공지 띠, 빨간 느낌표가 화면 사방에 → 눈이 쉴 곳이 없음
- 버튼 크기·모양·위치 규칙이 없음 → "출동"이 어디 있는지 찾아야 함

**우리 규칙 (화면 3층 구조):**

| 층 | 위치 | 규칙 |
|---|------|------|
| ① 상단 바 | 맨 위 얇은 띠 | 재화 **최대 3개** + 설정 버튼. 그 외 없음 |
| ② 무대 | 가운데 (화면의 70% 이상) | **사무소 내부.** 배너·버튼 올리지 않음. 사무소 물건 자체가 클릭 가능 |
| ③ 하단 독 | 맨 아래 한 줄 | 메뉴 **최대 5칸** + 오른쪽에 큰 **[출동]** 버튼 하나 |

- **주 버튼은 딱 하나:** `[🌙 출동]`. 가장 크고, 항상 같은 자리(오른쪽 아래). 이 게임의 핵심 루프가 "낮 준비 → 밤 출동"이기 때문.
- **알림 점(빨간 점)은 "지금 할 일이 있을 때만"** 하나. 느낌표·NEW·UP 뱃지 남발 금지.
- **이벤트 배너 상시 노출 금지.** 필요해지면 사무소 안의 물건(예: 게시판)에 붙입니다.

## 3. 용어 사전 (헷갈리는 UI 용어)

| 용어 | 뜻 | 우리 게임에서 |
|------|----|-------------|
| **하단 독 (Dock) / 탭 바** | 화면 맨 아래 고정된 메뉴 줄 | ③ 메뉴 5칸 + 출동 버튼 |
| **바텀 시트 (Bottom Sheet)** | 아래에서 **위로 쓱 올라오는 패널.** 뒤 화면이 살짝 보임 | 메뉴 칸을 누르면 올라오는 창 (예: 대원 목록) |
| **풀스크린 (Full screen)** | 화면 전체를 덮는 창 | 서울 지도처럼 넓은 화면이 필요한 기능 |
| **핫스팟 (Hotspot)** | 배경 그림 속 **클릭 가능한 물건** | 벽 지도, 화이트보드, 전화기 등 |
| **CTA (Call To Action)** | 화면에서 가장 누르게 만들고 싶은 버튼 | `[🌙 출동]` |
| **모달 (Modal)** | 열려 있는 동안 뒤 화면을 못 만지는 창 | 바텀 시트·풀스크린 모두 모달로 취급 (입력 규칙 4번) |

> 정리: 말씀하신 "사무소 내부 보여주고 그 아래에 각 기능" = **무대 + 하단 독**, 기능을 누르면 올라오는 창 = **바텀 시트**입니다. 용어 정확하게 쓰셨어요.

## 4. 메뉴 목록 (언제 열리나)

| 메뉴 | 하는 일 | 여는 방법 | 열리는 형태 | 열리는 Gate |
|------|--------|----------|-----------|------------|
| 🌙 **출동** | 오늘 밤 갈 균열 선택 → 밤 전투 시작 | 출동 버튼 / 벽 지도 | 풀스크린 (서울 지도) | **Gate 1** (을지로 1곳만) |
| 👥 대원 | 퇴마사 목록, 파티 편성, 기질·트라우마 확인 | 독 / 화이트보드 | 바텀 시트 | Gate 2 |
| 🕯️ 회복 | 트라우마 치료(굿), 휴식 | 독 / 제단 | 바텀 시트 | Gate 2 |
| 🚐 파견 | 2분대 자동 파견 (정화된 구역만, 상한 있음) | 독 / 승합차 창문 | 바텀 시트 | Gate 3 |
| ☎️ 대여 | 대여 시장 (다른 사무소와 퇴마사 빌려주기/빌리기) | 독 / 공중전화 | 바텀 시트 | Gate 4 |
| 🏠 꾸미기 | 사무소 가구 배치 | 독 / 소파 | 무대 위 편집 모드 | 미정 (Gate 1은 금지) |
| ⚙️ 설정 | 소리, 키 설정, 언어 | 상단 바 | 바텀 시트 | Gate 1 (최소) |

- 아직 안 열린 메뉴는 **독에서 아예 숨깁니다** (잠금 아이콘으로 칸 채우기 X → 그게 덕지덕지의 시작).
- Gate 1의 로비 = 사무소 배경 + `[🌙 출동]` + ⚙️. 끝.

## 5. 확장 구조: "등록표 한 줄 = 메뉴 하나"

새 기능을 추가할 때 로비 코드를 고치지 않도록, 로비는 **등록표를 읽어서** 독 칸·핫스팟을 그립니다.

```ts
// src/data/lobby.data.ts  (예정 — 모양만 보여주는 예시)
export const LOBBY_FEATURES: Record<LobbyFeatureId, LobbyFeatureData> = {
  sortie:   { labelKey: 'lobby.sortie',   slot: 'cta',  hotspot: 'wallMap',    panel: 'fullscreen',  unlock: 'gate1' },
  roster:   { labelKey: 'lobby.roster',   slot: 1,      hotspot: 'whiteboard', panel: 'bottomSheet', unlock: 'gate2' },
  recovery: { labelKey: 'lobby.recovery', slot: 2,      hotspot: 'altar',      panel: 'bottomSheet', unlock: 'gate2' },
  // 새 기능 = 여기 한 줄 + src/ui/features/<이름>/ 화면 파일 하나
};
```

- 화면(React 컴포넌트)은 `src/ui/features/<기능이름>/`에 기능별로 따로. 서로 import 하지 않음.
- 기능을 여닫는 건 `openFeature(id)` / `closeFeature()` 하나로만 → 입력 스택(`modal`)도 여기서 자동으로 쌓고 뺌 (규칙 4).
- `ESC` = 열린 창 닫기, 창이 없으면 아무 일 없음. 창 닫은 직후 클릭 없이 키가 바로 먹어야 함.

## 6. ❓ 같이 정해야 할 것

1. **사무소 시점:** 비스듬히 내려다보는 **쿼터뷰**(토끼 카페 스크린샷 같은) vs 옆에서 보는 **횡스크롤 단면**(방 하나를 정면으로)?
2. **사무소를 클릭할 수 있게 할까?** (핫스팟) — 몰입감은 좋지만 그림 작업이 늘어남. 하단 독만 두고 핫스팟은 나중에 추가도 가능.
3. **로비에 캐릭터 일러스트를 크게 세울까?** (가챠 게임처럼 대표 캐릭터 1명) vs 작은 대원들이 사무소에서 돌아다니기?
4. **재화 3개는 무엇?** 후보: 돈(💰), 영력/부적 재료(🔮), 굿 비용용 재화(🧧)…
5. **메뉴 이름/구성:** 위 5칸(대원·회복·파견·대여·꾸미기)에서 빼거나 바꾸고 싶은 것?
6. **바텀 시트 높이:** 화면 절반 / 70% / 기능마다 다르게?

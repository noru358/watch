# 🎮 게임 구조 설계 — 결정 기록

> 사용자와 대화하며 정한 내용을 쌓아 두는 곳. "✅ 결정" = 확정(나중에 바뀔 수 있음), "🤔 논의 중" = 아직 열려 있음.
> 화면(로비) 배치는 [`LOBBY_DESIGN.md`](LOBBY_DESIGN.md), 코드 규칙은 `ARCHITECTURE.md`.

## 1. 한 줄 요약
허름한 을지로 사무소의 귀차니스트 천재 해결사가 **의뢰를 받고 → 밤에 퇴마하고 → 월세를 막는** 게임. (은혼 해결사 사무소 느낌)

## 2. 결정 사항

| 항목 | 결정 | 상태 |
|------|------|------|
| 플랫폼 | 스팀(PC) 먼저 → 모바일. 같은 코드(Phaser) | ✅ |
| 수익 모델 | PC = 유료 판매(+선택적 과금 가능), 모바일 = 무료+과금 | ✅ |
| 시점 | 비스듬한 탑다운 픽셀아트, 한 화면 ≈ 광장 하나 | ✅ |
| 메인 캐릭터 | **사무소장 1명 고정.** 플레이 다양성은 **퇴마 도구 교체**로 | ✅ |
| 한 판 | **의뢰 1건 = 밤 1판 = 10~15분** | ✅ |
| 허브 | 걸어다니는 사무소+골목 + 하단 독 단축 버튼 (일단 만들어 보고 수정) | ✅ (시험) |
| 스토리 | 직접 쓴 스토리 의뢰 + 자동 생성 일반 의뢰 혼합 | ✅ |
| 긴장 장치 | 밀린 월세/빚 — 스토리에도 엮음 | ✅ |
| 대원 획득 | 귀신을 성불/설득 → 대원. 확률 영입 + 스토리 영입 | 🤔 비율·조건 논의 중 |
| 실패 페널티 | 후보: 트라우마, 장비 손실, 경험치 손실, 재화 손실 | 🤔 조합 논의 중 |
| 아트 | 코지 픽셀아트 바탕 + 색보정·조명으로 시티팝 무드 덧씌우기 | 🤔 |

## 3. 핵심 루프
```
☎️ 수임(의뢰 접수) → 🧰 준비(도구·동행 대원) → 🌙 출동(방 5~8개 + 원인 귀신)
→ 💰 정산(수임료·전리품·성불 대원) → 🏢 경영(월세·회복·성장) → 다시 수임
```

## 4. 퇴마 도구 (후보)
| 도구 | 스타일 |
|------|--------|
| 🧧 부적 | 원거리 · 설치 |
| 🔔 방울/신칼 | 근접 · 굿 리듬 |
| 📱 퇴마 앱 | 촬영 → 봉인 |
| 🍶 소금/막걸리 | 범위 · 정화 |

전투 버튼은 **4개 이하** (공격 · 회피 · 도구 스킬 · 대원 호출) — 모바일 조작 한계 때문.

## 5. 1인 개발 에셋 부담을 "구조로" 줄이는 원칙
1. **귀신 = 이펙트.** 귀신은 그림자·글리치·파티클 위주로 표현 → 걷기 애니메이션 시트가 거의 필요 없음. 공포 분위기에도 더 맞음.
2. **색 바꾸기(팔레트 스왑)로 변종 만들기.** 귀신 1종 그림 → 색·크기·이펙트만 바꿔 3변종.
3. **방은 조립식.** 구역마다 타일셋 1개 + 방 조각 몇 개를 섞어 의뢰마다 다른 현장처럼 보이게.
4. **분위기는 코드가 담당.** 시티팝 무드(노을 그라데이션, 네온 번짐, 비 반사, 필름 노이즈)를 그림이 아니라 조명·색보정 효과로 → 그림은 단순해도 됨.
5. **스토리는 글 + 초상화.** 컷신 대신 대화창 + 인물 초상화(감정 2~3개씩).
6. **허브는 한 화면.** 사무소 + 골목 1장. 넓은 마을 만들지 않음.
7. **캐릭터는 작게.** 16~24px 정도 → 애니메이션 프레임 부담 감소.
8. **재미 먼저, 그림 나중.** Gate 1~2는 네모·임시 그림으로 재미를 검증하고, 통과한 것만 그림을 그림.

## 6. 🤔 남은 질문
- 실패 페널티: 4개 다 걸면 너무 아픔(특히 모바일 과금 게임에서 "돈 내고 손실 막기"로 보이면 반감). 의뢰 난이도별로 골라 걸기?
- 성불 대원: 확률 영입과 스토리 영입 비율, 일반 귀신도 대원이 되는가?
- 모바일 과금 대상: 꾸미기/편의/시즌 패스 위주? (대여 시장과 현금 연결은 금지 — ARCHITECTURE §6)
